출처: 실제 공모전 7건(코스콤·소마·알파프로젝트·하나증권·KIC·현대차·DCA)의 결과물과 채팅 기록 분석(materials/research.md, materials/playbook.md).

## 1. 여섯 단계

| 단계 | 명령 | 들어오는 것 | 나가는 것 | 누가 판단하나 |
|---|---|---|---|---|
| 0 요강 고정 | `/contest:init` → `/contest:research` 1부 | 요강 URL·양식·Q&A·접수 폼 | 10-research/brief.md | 에이전트 |
| 1 조사 | `/contest:research` | 주최사·분야·사용자·경쟁 | org.md, domain.md, users.md, competitors.md | 에이전트(병렬) |
| 2 주제 | `/contest:topics` | 조사 5종 + 사용자 기준 | topics.md(후보 3~5, 순위, 추천) | **사용자가 고른다(관문 1)** |
| 3 고도화 | `/contest:refine` | 선택 주제 | evidence.md, design.md, judge-preview.md | 자동 점검(관문 2) |

## 2. 관문

| 관문 | 조건 | 통과 못 하면 |
|---|---|---|
| 1 주제 선택 | 사용자가 후보 하나를 고른다. 고른 이유·버린 후보의 이유·흡수한 요소를 CONTEST.md에 사용자 문구 그대로 기록 | 후보를 다시 만들거나 조사를 보강 |
| 2 고도화 자동 점검 | ① 문제 크기가 E-ID 달린 숫자 하나 이상 ② "여기서만 되는 기능" 둘 이상 ③ 범위 경계 문장 ④ 성공 기준 표(지표·목표·검증 방법) | `/contest:refine`로 돌아감 |
| 3 스펙 승인 | 사용자가 PRD·SRS를 읽고 승인. 승인 문구 기록. 열린 질문에 기한 | 수정 후 재제시 |
| 산출물 | fact-checker 정정 0건, 자리표시 0건, S1 금칙 0건, 글자 수·형식 통과 | 산출물 재작성(스펙은 안 건드림) |

## 3. 사용자가 실제로 개입한 지점 (대화 분석)

1. 분야·후보 선택 — 추천을 참고하되 뒤집기도 한다
2. 아이디어 기각과 자기 안 제시 — 이유가 구체적(개연성·타깃 심리·안전·물류·진짜 바이럴)
3. 본인·팀원 경험, 이력, 연락처, 서명 채우기
4. 문체·사족 지적 — 예시 문장 한 줄로 ("이런 일은 드물지 않다 — 사람이라면 안 쓸 말")
5. 제출(폼 입력·임시저장·첨부)

그 밖의 일(요강 추출, 리서치, 초안, 검증, 문서화)은 전부 위임됐다. 에이전트는 이 다섯 지점에서만 멈추고 묻는다.

## 4. 사용자의 말 → 동작

| 사용자가 쓴 말 | 할 일 |
|---|---|
| "(URL) 조사해줘", "대회 전반을 조사" | `/contest:research` |
| "분야는 어디가 좋을까?" | topics.md §0 분야 표 + 추천 1·차선 1 |
| "직무 관련으로 생각해보면?" | 후보를 취업 목표 축으로 다시 생성 |
| "이거 겹치지 않을 주제일까?", "참신한지 판단해줘" | competitors.md 두 축 갱신 + 다듬는 방향 |
| "무조건 수상하고 싶은데 추천한다면?" | 수상 관문 표로 단독 추천 + 확률 올리는 조건 5~6개 |
| "더 자세히 조사", "철저히", "해외 선례", "내가 판단할 수 있도록" | evidence.md 보강(✅⚠️❓, 남은 불확실성) |
| "구글문서로 만들어줘 내가 읽고 수정할 수 있게" | 편집 가능 문서 + 머리 메모(글자 수·붙여넣기·제출 전 지울 것) |
| "AI가 쓴 것 같지 않도록 + 내용이 우수하게" | 내용 보강과 문체 교정을 분리해 두 번 |
| "(문장 예시) 사람이라면 안 쓸 말" | 그 패턴 전수 검색 → style-ko.md 기준 재작성 → check_style 0건 |
| "심사위원으로 혹독하게 검토" | `/contest:judge` |
| "전부 반영", "반영해줘" | 변경 로그에 승인 문구와 함께 기록 → 재빌드 → 재검증 |
| "프로젝트 외의 내용은 다 빼줘" | 장당 주장 1 + 근거 1로 축소 |
| "일정과 내역 정리해줘" | `/contest:status` |

## 5. 고도화 라운드의 순서 (반복 관찰)

내용 보강 → 문체 → 사실성(경험 없음을 밝히고 보도 사례로) → 심사위원 모의 1~2회 → 문체 재점검. 심사위원 모의는 "초안 작성자와 다른 컨텍스트"가 한다. 실제 작업에서는 같은 에이전트가 두 번 자기 비판을 했지만, 플러그인에서는 judge-simulator를 분리한다.

## 6. 작업 공간 규칙

- 공모전 하나당 폴더 하나. 다른 공모전 재료(링크·초안)가 들어오면 작업 전에 확인을 구한다. 실제로 한 공모전 링크를 다른 공모전 채팅에 붙여 초안이 생겼다가 폐기됐다.
- 파일 이름에 버전과 바뀐 점을 적는다: `기획서_v3.2_출처포함.md`. 머리에 변경 로그.
- 작업용 → 양식본 → [최종] 세 단계로 파일을 나눈다. 양식에서 직접 고친 내용은 작업용에도 되가져온다.
- 공식 마감보다 앞선 실질 마감(−3일, 팀이면 −5일)을 CONTEST.md에 둔다.
