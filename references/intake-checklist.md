# intake-checklist.md — 요강·양식·플랫폼 전수 추출

brief-analyst가 채우는 항목. 요강 원문 문구를 그대로 옮기고 해석은 분리한다.

## 1. 확인 항목 (실제 사례)

| 확인할 것 | 왜 | 실제 예 |
|---|---|---|
| 양식 항목 구조와 변경 가능 여부 | 목차가 곧 양식 | 소마: □·ㅇ 추가·삭제·순서 변경 금지, 기본 표 삭제 금지 / 알파: 소개·목표 두 칸 / 현대차: 01~04 / 관광데이터: 4항목 수정 금지 |
| 분량·형식·용량 | 검수 기준 | 하나증권 5,000자(공백 포함)·첨부 3개·10MB / 관광데이터 5쪽·12pt·PDF 10MB / 소마 요약 1쪽+본문 10쪽·□15pt·ㅇ13pt·표11pt / KIC 슬라이드 12장(표지·부록 제외 10) |
| 심사 기준·배점·감점·가산점 | 본문이 답할 곳 | 알파: 4영역 각 25점, 감점(외부 콘텐츠 소개만·조사만·2장 이내·무리한 편성), 가산점(공모전 출품 예정·동아리 기반) / 소마 ✅ 질문 6개 / 현대차 참고자료 가산점·숏폼 별도 특별상 |
| 필수 요소 | 빠지면 실격 | 관광데이터 TourAPI 필수 / 현대차 Pleos SDK / 코스콤 MCP 서버 제작·배포 |
| 개인정보·서명·메일 규칙 | 실격 사유 | 현대차: 심사 자료에 이름·연락처·소속 금지, 팀원 서명, 메일 CC / 알파: 서명 이미지·팀 구성 시트 |
| 단계와 일정 | 실질 마감 | KIC 예선 기획서 → 상호평가 → 본선 MVP 19일·발표 10분 / 현대차 1차 접수 → 2차 PT(기기 두 대) → 전시 |
| 운영진 Q&A·FAQ | 양식에 없는 규칙 | KIC 18건: 출처 기재만으로 허용 아님(약관 직접 확인), 기존 코드는 기존/응용/신규 구분, 임시저장≠최종제출, 파일 교체는 메일로 취소 후 재제출 |
| 플랫폼 메커니즘 | 전략이 바뀜 | DAKER ELO 1v1 상호평가 30%+전문가 70%, 최소 투표 미달 시 득표 무효, 기획서가 타 참가자에게 공개·다운로드 가능 → 외부 링크 비권장 |
| 접수 폼 실제 필드 | 포스터에 없음 | 하나증권: 제목 300자, 본문 5,000자 일반 텍스트, 첨부 PDF/JPG/PNG 3개·10MB, 파일명 '지원자명_보충자료명', 폼 타이머 1시간 40분 |
| 혜택과 사용자 목표의 연결 | 참가 동기·우선순위 | 하나증권 본선 10명 서류전형 면제 5년 유효 → 2028 하반기 공채 안 / KIC 최우수 → 청년인턴 필기 5% 가산 |
| 애매한 규정 | 운영진에게 묻기 | KIC 데이터 출처 표기 충분성 → "부족" 답변 후 약관 전수 확인 |

## 2. 수집 방법
- 공고 페이지, 포스터, 채용·접수 사이트, 운영 플랫폼(DAKER 등) 게시판, 링커리어·커뮤니티 재게시글, 보도자료.
- 접근이 막힌 페이지는 그렇다고 적고 사용자에게 직접 열어 달라고 한다.
- 동의 화면 뒤의 접수 폼은 사용자 동의 없이 넘어가지 않는다. 필드만 확인하고 멈춘다.
- 선행 회차·같은 플랫폼의 다른 대회 결과(수상작·심사 방식·제출물 형태)도 함께 적는다(domain.md §3).

## 3. 출력
brief.md 전 절 채움 + "운영진에게 물을 것" + 일정표(실질 마감) + CONTEST.md 기본 정보 갱신.
