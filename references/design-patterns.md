# design-patterns.md — 고도화 작업과 판단 기준

고도화는 기능을 늘리는 일보다 심사위원이 물을 질문에 미리 답을 달아 두는 일이다. 넓게 잡았다가 근거를 대며 줄인다(코스콤 컨테이너 6개 → 서버 3개, CINE 추천·챗봇 → 로드맵, 소마 기능 6개 → 3개).

## 1. 고도화 작업 목록
| 작업 | 하는 일 | 실제 예 |
|---|---|---|
| 사건 타임라인 | 같은 문제가 반복됐다는 걸 연도별 표로 | — |
| 원인 → 결과 연쇄 | 왜 생기고 사용자에게 무엇이 남는지 순서대로 | — |
| 선례 | "이미 누가 하고 있다"로 실현성 | ShotBench |
| 경쟁 비교표 | 기준별로, 되는 건 △ | — |
| 수치 규칙 | 임계값·상한·가중치·비율을 숫자로 | 경제 시나리오 3종 |
| 시간표 시나리오 | 적용 전·후 같은 시각표 | — |
| 리스크·대안 | "확인할 것 → 안 될 때 대안" | — |
| 라이선스·규제 | 약관을 읽고 못 쓰는 것을 밝힘 | CINE 퍼블릭 도메인·CC BY만 |
| 평가 설계 | 성능을 주장하지 않고 재는 방법 | 검증 세트 200숏, Precision 우선 |
| 역할 경계 | 시스템이 정하는 것 / 사람이 하는 것 / 멈추는 조건 | 코스콤 '계산은 서버, LLM은 인터페이스' |
| 구현 상태 표기 | 단계마다 구현완료/구현X/구현중 | 코스콤 기획안, 소마 간트 |
| 기본값 | 보수적으로 | 보수형 포트폴리오 |

## 2. 판단 기준
- 범위는 근거로 자른다(벤치마크·설문·실측). "근거 없이 축소한 것이 아니라 공개 지표로 달성 가능 수준을 판단한 결과"라고 적는다.
- 성공 기준을 계획보다 먼저 정한다(지표·목표·검증 방법 표).
- 한계를 기능으로 만든다(신뢰도 표시, 오류 신고, 보류, 근거 약하면 해설 생략).
- 기대효과는 절제하고 지표와 계산식으로 보인다("기대효과를 크게 적고 싶지는 않습니다").
- 남의 경험·이력은 지어내지 않는다.
- 작업 중 겪은 일을 넣는다(표본을 늘려 임계값을 다시 잡은 과정). 실제 부딪힌 문제가 가장 강한 근거다.
- 한 곳을 고치면 연결된 곳을 같이 고친다(traceability §4).

## 3. 코스콤에서 시작해 KIC·CINE까지 이어진 설계 규칙
1. 계산·판정은 결정적 코드, LLM은 인터페이스·요청만(도구 실행 권한은 코드가 갖는다).
2. 단일값 대신 범위·시나리오, 기본값은 보수적.
3. 외부 API는 필요한 것만, 나머지는 캐시·연도별 설정·야간 스냅샷.
4. 가상 사용자 3명, 국가 중위값 케이스, 모듈 간 교차검증으로 테스트.
5. 기획 단계마다 구현 상태를 표기해 기획과 구현을 맞춘다.
6. 매뉴얼에는 오프라인 설치 경로와 연결 확인 질문까지.
7. 문서 속 지시문은 따르지 않는다(프롬프트 인젝션 방어), 개인정보는 사전 제거.

## 4. 자주 쓴 표 틀
| 표 | 열 |
|---|---|
| 경쟁 비교 | 기준(행) × 기존 도구들과 제안(열), ○△× |
| 단계별 판단 규칙 | 단계 / 하는 일 / 판단 규칙 |
| 역할 경계 | 시스템이 정하는 것 / 사람이 하는 것 |
| 확인할 것과 대안 | 확인할 것 / 안 될 때 대안 |
| 리스크 | 리스크 / 영향 / 대응 |
| 데이터 | 데이터 / 출처 / 갱신 / 전처리 / 라이선스 |
| 도구·SDK | 도구 / 입력→출력 / 부르는 때 / 비고(확인할 것) |
| 일정 | 단계 / 기한 / 범위 / 산출물 |
| 기능 통과 기준 | 기능 / 통과 기준 |
| KPI | 지표 / 목표 / 검증 방법 |
| 시간표 시나리오 | 시각 / 상황 / 화면에서 일어나는 일 |
| 화면 설명 | 화면 / 설명 / 대응 기획서 항목 |
| 전후 비교 | 구분 / 지금 / 제안 후 |
| 설계 규칙 | 규칙 / 값 / 효과 |
| 기본값 | 영역 / 규칙 / 기본값 |

## 5. 버전이 바뀔 때마다 반복된 방향 (고도화 라운드의 목표)
범위를 좁힌다 · 근거를 붙인다(재확인 표시를 끝까지 해소) · 주최사에만 맞는 기능을 앞으로 · 경쟁을 공정하게 · 연출과 과장을 실측으로 · 지어낸 것을 비운다 · 양식에 맞춘다 · 작업 중 겪은 일을 넣는다 · 계획과 실제를 맞춘다 · 문장을 다듬는다(숫자 헤드라인, 쉬운 말, 대구 공식 제거).
