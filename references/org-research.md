# org-research.md — 주최사·분야·사용자·경쟁 리서치 방법

## 1. 주최사 5단 보고 (하나증권에서 쓴 구조)

1. **원하는 것** — 비전·신년사·헌장·수상 이력·채용 공고·CEO 발언.
2. **아픈 곳** — 실적 급감, 과태료·제재, 민원, 국감 지적, 인력 이탈, CIO 공석. 기획서에서는 필요성의 근거로만, 조심스럽게.
3. **남들은 뭘 하나** — 경쟁사·그룹사가 이미 하는 것을 주제별 표로. 끝에 "레드오션 판정" 한 줄.
4. **왜 지금인가** — 법 개정·시행일, 감독기관 요구(날짜), 신제품 출시(며칠 됐는지), 조직 신설. 우리 주제와 연결 문장.
5. **빈틈** — ⭐ 표시. 각 빈틈에 근거.

덧붙일 것: 최근 6개월 연표(출처 포함), 주최사 자산(채널·ID·데이터·플랫폼·SDK·오프라인 거점·그룹사), 용어·호칭(하나금융 '손님', 감독기관 용어).

## 2. KIC에서 더 깊게 간 것 (대형 기관일 때)
조직도(실 단위), 투자·업무 프로세스 단계, 위원회 구조, 정책 문서 조항 번호, 연간 이슈(TPA·전략투자·국감 지적), AI 도입 타임라인(조직 신설·발주 금액), 공개 데이터. "주최사가 스스로 선언한 의무"를 찾으면 문제 정의의 뼈대가 된다.

## 3. 분야 조사 (domain.md)
- 시장·제도 수치(출처 기관명 함께), 공개 모델·API 벤치마크(범위를 자를 근거 — ShotBench 항목별 정확도로 MVP 결정), 데이터 소스 후보와 **라이선스**.
- **선행 대회·전년도 수상작**: 같은 플랫폼의 다른 대회 결과(대상=개인 참가자였다는 식의 사실), 수상작 제목과 평가받은 점, 심사 구성(내부 → 외부 전문가 → 임직원 선호도). 광고형은 수상작 문법 6개를 뽑는다.
- 해외·타 산업 선례와 효과 수치.

## 4. 예상 사용자 (users.md)
- 1차·2차 사용자와 규모(수치). 페르소나 2~3(상황·지금 하는 방법·불편·바라는 것).
- 사람 이야기: 보도 인터뷰(매체·인물), 판결(청구액 중 인정액), 민원 건수, 게시글 분석(커뮤니티·건수), 자체 설문(표본·대상·한계 명시 — 멘토 7명 '소규모 정성').
- 현재 여정(as-is) → 제안 후 유저플로우(to-be) → 같은 시각표의 전후 비교.
- 본인 경험이 없으면 생성하지 않는다. "제가 직접 겪은 적은 없어서 겪은 분들 이야기를 찾아봤습니다"로 쓸 재료를 확보한다.

## 5. 경쟁 환경 (competitors.md) — 중복 점검 두 축
- **기존 서비스**: 기능 단위로 어디에 이미 있는지. 해외에 있고 국내에 없으면 "실현 가능성 근거"로 전환.
- **경쟁 참가자**: 플랫폼 팀빌딩 게시판·커뮤니티 모집글·전년도 수상작에서 아이디어 유형을 모아 몰림 정도를 추정.
- 비교표 초안: 경쟁 도구가 되는 건 △ "조건부"로 공정하게. 전부 ×면 심사위원이 믿지 않는다.
