# evidence-rules.md — 근거 원장과 할루시네이션 방지

## 1. 원칙
1. 산출물에 들어가는 모든 숫자·인용·고유명사·날짜는 evidence.md의 E-ID를 갖는다. 없으면 [확인 필요]로 쓰고 제출 전에 해소한다.
2. 출처 등급: ✅ 1차 출처를 직접 열어 확인(공시 원문·법령·공식 보도자료·API 응답) / ⚠️ 2차 출처(기사·블로그)나 추정 / ❓ 미확인. ⚠️는 본문에 쓰되 출처를 밝히고, ❓는 본문에 쓰지 않는다.
3. 직접 집계는 방법·도구·질의·기간·집계일을 함께 적는다("SEC EDGAR 전문검색 API, 2026-10-01~31, forms=8-K, 매칭 보유 510개사 — 작성 시 직접 집계").
4. 인용문은 원자료에서 찾을 수 있어야 한다(설문 응답에 없는 인용이 들어갔던 사례). 따옴표 인용은 짧게, 나머지는 바꿔 쓴다.
5. 연출 숫자는 금지. 시연 장면도 실측 평균으로("하루 8-K 42건" → 525÷22영업일 = 24건).
6. 절대 표현('전혀', '모두', '사실상 0', '기존에 없다') 대신 조건이 붙은 문장. "기존에 없다"고 단정하지 않고 검증할 지표로 차별성을 보인다.
7. 사람의 것(팀원 경험·이력·연락처·서명·본인 체험)은 생성하지 않는다. 【】로 비우고 묻는다. 경험이 없으면 "직접 겪은 적은 없어서 겪은 분들 이야기를 찾아봤습니다"처럼 사실을 밝힌다.
8. 추측은 "제 추측입니다", 가상은 "가상"·"[예시값]"으로 표시한다(신뢰도 0.86은 예시값, 협업 부서 목록은 제 추측).
9. 라이선스는 약관을 읽고 표로 남긴다. 운영진이 "출처만 적는 걸로는 부족하다"고 답한 사례가 있다. 못 쓰는 데이터는 "뺀 데이터와 이유"로 적는다.
10. 남은 불확실성 표(항목·상태·대응)를 유지한다. 비공개 기준은 설정값으로 설계해 우회한다.

## 2. E-ID 작성 양식
`| E017 | 2021~2025 10대 증권사 전산장애 201건, 보상 98건(48.8%) | 201건 / 98건 | 뉴시스 2026-03-15 "증권사 전산오류 피해 보상은" (김상훈 의원실·금감원 자료) | 2026-11-05 | ⚠️ | 기사 인용, 원 자료 미확인 |`

## 3. fact-checker가 보는 것
- 산출물의 숫자 → E-ID 존재·값 일치(trace_numbers.py로 1차, 사람 눈으로 2차)
- 같은 숫자가 문서 여러 곳에서 같은가, 요약과 본문이 같은가
- 인용문 → 출처에 실제로 있는가
- 날짜·요일·시각 표기 일관성(24시간제, 요일)
- 경쟁 도구 평가의 공정성(되는 걸 ×로 쓰지 않았는가)
- 산출물 이름·기능 이름 통일
- 스펙 밖의 기능·수치가 들어왔는가(들어왔으면 산출물이 아니라 스펙 변경 요청으로 돌려보냄)
- [가정]·[예시값] 표기가 빠진 추정치

## 4. 실제로 새어 나간 사례 (검사 항목의 출처)
- 대화 중 지시였던 "(사용자 원칙: 성공 기준을 먼저 정의하고 실행)"이 KPI 표 머리에 남음
- 마크다운 별표 "**RAG(…)**를"가 변환되지 않고 보임, 물결표가 취소선으로 변환
- 그림 캡션 사이에 이미지가 끼고 그림 1에 캡션 없음
- 새로 넣은 기능이 목표·KPI·리스크에는 있는데 일정·개인 계획·담당·예산에는 없음
- 팀원이 빠진 뒤 화면 하나의 담당이 빈 채 제출
- 요약 칸의 BM과 본문 요금표 불일치
- 다른 서비스 절의 원칙 문구가 그대로 복사됨
- 팀원 이력을 추정으로 채웠다가 되돌림 — 처음부터 비웠어야 함
