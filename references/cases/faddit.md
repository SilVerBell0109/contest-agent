# 사례: 패크크(FADDIT Creator Crew) 2기 지원서 (2026.9, 9/10 마감)

- 유형: 프로그램 지원서(--type application). 주최사 패딧(FADDIT)은 패션 제작 플랫폼. 지원서 3문항.
- 함께 참고: 소마 지원서·자기소개서(평가 기준에 맞춰 문장만 다듬고 사실관계는 그대로; 경험 서술 순서 "동기 → 주제·구현 → 역할 → 배운 점 → 결과").

## 작업 순서
1. **주최사 조사 먼저**: 1기 심사 기준, 패딧의 사업 모델(무엇을 팔고 크루에게 무엇을 바라는가).
2. **문항 → 평가 축 매핑**: 3문항을 완주 가능성 / 제작 가능성·패딧 활용 / 펀딩 성공 가능성으로 번역. 문항 그대로 답하지 않고 축에 답한다.
3. **관통 프레이밍 한 문장**을 세 문항에 반복: "AI로 무엇을 만들지를 좁히고, 패딧으로 어떻게 만들지를 확정한다".
4. **선정 뒤 리스크를 지원자가 먼저 지움**: 주최사 가까이 산다는 사실 → "필요하면 당일 방문 가능" 한 문장이 어떤 수식어보다 강하다.
5. **함정 목록과 표현 교정표**: "AI로 디자인을 뽑았다"(✗) → "제가 정한 기준으로 시안 40장을 생성하고 3안으로 압축해 직접 수정"(✓). AI가 틀렸던 경험을 스스로 말하는 것이 신뢰 신호.
6. **사용자가 채워야 할 것만 묻기**: 확인 질문 4개 → 사용자가 번호로 답("1. 있음 2. 나중에 3. 모르겠음 4. 2인팀·주2회·거주 구") → 【 】 자리표시 초안 → 사용자가 자기 문장으로 쓴 지원동기를 붙여 넣음.
7. **증거 첨부 3종** 제안: 시안 압축 과정, 렌더↔도식화 대응표, 실물 사진("3번이 있으면 1등 확률이 크게 올라감").

## 지원서형 공통 규칙
- 글자 수 제한은 줄바꿈 2자 기준으로도 맞춘다. 붙여넣기용 txt(□·①·→만) 동시 생성.
- 본문은 합쇼체+1인칭, 경험은 "동기 → 무엇을 → 역할 → 배운 점 → 결과".
- 지원 동기·개인 경험 문장은 사용자가 직접 쓴다(【 】). Claude는 구조·근거·교정만.
- 심사자가 "선정하고 나서 걱정할 것"(거리, 시간, 역량, 팀 유지)을 목록으로 만들어 문장 하나씩 선제 답변.
- AI 활용은 숨기지 않고 "내가 정한 기준으로 AI를 썼다"로 쓴다.
