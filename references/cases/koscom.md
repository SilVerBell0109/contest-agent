# 사례: 코스콤 AI Agent Challenge 2025 '은퇴 설계 AI 에이전트' (2025.9~12, 우수상·코스콤 대표이사상)

- 유형: 개발형(MCP 서버 구현·배포). 팀 4인, 사용자는 유일한 개발자(설계·구현·배포), 기획·사용자 분석은 팀원.
- 제출물: 기획안, GitHub, Docker Hub 이미지 3개(적립·투자·인출, 오프라인 .tar 포함), 매뉴얼, Claude 대화 공유 링크, (시연 영상·발표 자료 추정).
- 일정: 9/14~18 기획안 → 10/28~11/22 구체화·구현·테스트 → 11/22 녹화 → 11/23~27 매뉴얼 → 12/6 코드 해설 문서 → 12/9 발표.

## 주제 경로
- 다른 후보와 비교한 흔적 없음. 금융권 자료를 읽으며 준비. '은퇴 코파일럿' → '은퇴 설계 AI Agent'.
- 1장은 기관명 붙은 통계 세 묶음(희망 은퇴연령 73.3세, 65세 이상 1,000만 명, 퇴직연금 431.7조 원) → 문제(자사 상품 편향, 분산 자산, 세제 미반영) → 핵심 가치 한 줄 "전 자산 통합 관리와 중립적 최적 설계" → 고민 3개 ↔ 서비스 3개(적립·투자·인출메이트) 1:1 대응.

## 고도화
- 범위는 넓게 시작해 좁혔다: 컨테이너 6개·몬테카를로·ESG → 서버 3개만 배포. 공통·외부연동 서버, SQLCipher, OCR은 최종물에서 제외.
- 계산 규칙을 전부 수치로: 경제 시나리오 3종, 필요 자본(연금현가법+안전인출률 평균+의료비 버킷), 대체율 70%, 포트폴리오 비율 3종, 가드레일 ±20%/±10%, 3버킷, 절세 순서(연금계좌 → ISA → 일반).
- 차별점 6개 중 핵심은 "결정적 계산 기반의 신뢰성": 계산은 서버, LLM은 자연어 인터페이스만. 이후 모든 공모전에 이어짐.
- 속도·토큰: 실시간 API 다중 호출 → DB 저장 후 주기 갱신, 필수 API만, 연도별 설정 모듈(KOR_2025).
- 기획 단계마다 '구현완료/구현X/구현중' 표기. 가상 사용자 3명 + 한국인 중위값 45세 케이스로 모듈 간 교차검증(7.4억 → 5.5억 재조정, 조정 순서: 지출 감소 → 저축 증액 → 은퇴 연기).

## 제작
- 기획안 목차: 배경 → 서비스 개요·구조(공통 UX, 메이트별 원칙 → 단계 → 산출물) → MCP 서버·도구 설계 → 특장점 6·기대효과 5.
- 매뉴얼: 개요 → 기능 → 환경 설정(온라인 pull/오프라인 .tar, config 전문, 연결 체크리스트) → 도구 가이드(질문 템플릿, 좋은/나쁜 질문 4쌍) → 문제 해결 → FAQ 4개. 초안의 예상 결과 숫자·이모지는 최종본에서 삭제.
- 발표 대비: 비개발 팀원용 코드 해설 문서(파일별 라인 범위).

## 결함·교훈
- 인출 원칙에 적립 문구가 그대로 복사된 곳 → 복붙 검수 항목.
- 회고에서 "계산 일치율 95% KPI 달성"이라고 썼지만 당시 자료로 확인 안 됨 → 회고 수치도 E-ID 필요.
- 교훈: "기술적으로 가능한 것과 실제로 좋은 서비스인 것은 다르다" — 기능을 덜어내는 기준은 '누구나 간단하고 가볍게'.
