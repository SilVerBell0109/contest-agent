# 사례: 제1회 하나증권 청년 금융아이디어 공모전 '장애 안심 모드' (2026.11.4~5, 제출 완료)

- 유형: 아이디어 제안형, 개인. 주제 "더 편리한 금융(MTS 편의성·새로운 손님 서비스)". 제출: 지원서 '아이디어 작성' 칸 공백 포함 5,000자 + 첨부 3개(PDF·이미지).
- 제목: "MTS가 멈춰도 손님의 주문은 멈추지 않는다: 하나증권V '장애 안심 모드'".
- 작업 파일: 기획서 1개(A 본문 + B 보충자료 재료 + B-7 문체 기준), 화면 예시 문서 1개. 하루에 완료.

## 주제 경로
- 첫 후보 '진짜체크'(직원 역방향 인증) → 사용자 "이거 겹치지 않을 주제일까?" → 두 축 중복 점검(Monzo·Alfa-Bank에 이미 있음, 링크 체크는 토스·하나원큐와 겹침) → 사용자 "MTS 편의성 분야가 적절할지 확인", "자세한 조사. 내가 판단할 수 있도록" → 장애 모드로.
- '보유종목 파수꾼'은 KIC 채팅 링크 오염에서 파생 → 폐기. 작업 공간 분리 규칙의 기원.

## 본문(A) 구성 — 양식 없는 아이디어형의 기준 뼈대
1-1 손님의 불편/위험(사건 하나 → 빈도 숫자 → 사람 이야기 → 문제 3개로 좁힘) / 1-2 기회 발견(범위 자르기 + 근거 5개: 금감원 요구, 새 앱 유입, 보상액 적음, 저녁장, 소비자보호헌장) / 1-3 핵심 아이디어(경계 문장 "복구는 전산팀 일, 이 아이디어는 손님 화면만") / 2-1 구성(시간순 표: 평시·감지·장애 중·복구 후) / 2-2 손님 경험 변화(전후 화살표 + 장면) / 2-3 실행 3단계(3·6·12개월, 협업 부서에 "(제 추측입니다)") / 3-1·3-2 기대효과 각 3개(절제) / 3-3 고려사항 4개(증빙 신뢰성, 오탐·과잉 공지, 개인정보, 기능 플래그) / 3-4 AI 활용 고지 + 참고자료.
- 문서 머리 메모: 붙여 넣을 범위, 4,914자/5,000자, □·① 글자 기호, 제출 전 삭제.
- "제가 직접 겪은 적은 없어서 겪은 분들 이야기를 찾아봤습니다" — 모르는 건 밝히고 보도 사례로.
