# judge-bank.md — 심사위원 예상 질문 은행

judge-simulator가 산출물에 맞게 고르고 바꿔 쓴다. 각 질문에는 "한 문장 답"과 근거 E-ID가 있어야 한다. 첫 질문의 답은 발표자가 외운다.

## 1. 어디서나 나오는 질문
| 질문 | 답의 뼈대 |
|---|---|
| 기존 A·B와 뭐가 다른가 | 기능 단위 비교표 + "되는 건 △로 인정" + 우리만 되는 둘 |
| 왜 지금인가 / 왜 이 주최사인가 | 날짜 붙은 변화(법·제품·조직) + 주최사 자산에 엮인 기능 |
| 이미 있는 서비스를 쓰면 되지 않나 | 범용·블랙박스·정책 비연결·배치 환경·비용 → 있으면 입력 소스로 병합 |
| 숫자는 어떻게 뽑았나 | E-ID, 직접 집계 조건, 실측 vs 가정 구분 |
| 오탐·오류가 많으면 안 쓰게 되지 않나 | 임계치·상한·피드백 학습·기본값 보수적 |
| 환각·잘못된 판정은 | 결정적 계산, 근거 문장 강제, 다른 모델 재확인, 보류, 하네스 수치 |
| 개인정보·보안·법규는 | 최소 수집·암호화·보관 기간·기기 전용·관련 법 명시 |
| 데이터·모델 라이선스는 | 약관 확인 표, 뺀 데이터와 이유, 교체 후보 |
| 기간 안에 되나 / 팀이 할 수 있나 | 기능×통과 기준, 간트+버퍼, 축소 순서, 역량 근거 |
| 측정은 어떻게 | 지표·목표·검증 방법·데이터 분리·측정 안 하는 것 |
| 비용·ROI는 | 1단계는 기존 체계 연결이라 범위가 가장 작다는 식의 구조 답변 + 측정 지표 |
| 확장성은 | 단계별 로드맵, 버린 후보를 1순위로 흡수 |
| 사용자는 정말 원하나 | 설문·인터뷰·게시글 분석(표본·한계 명시), 사람 이야기 |
| AI를 어디까지 썼나 | 고지 문단 그대로. 축소하지 않는다 |

## 2. 사례별 실제 질문
**KIC(개발형, 에이전트)**: RepRisk·MSCI 쓰면 되지 않나 / 13F는 미국 주식만인데 / ESG는 식상하다 / 오탐이 많으면 안 보게 된다 / 환각은 / 중국산 모델 문제는 / 매매 판단에 쓰나 / 기존 사내 AI 플랫폼과 관계는.
**하나증권(아이디어형)**: 긴급공지·ARS 비상주문은 이미 있는데 뭐가 다른가(첫 질문, 세 가지로 답) / "보상 검토 대상" 알림이 민원을 늘리지 않나 / 앱 기록을 손님이 사후 조작하면 / 가상 대기실은 어차피 주문을 못 하는데 왜(가장 약한 항목은 길게 방어하지 말고 우선순위가 낮은 이유로 넘김) / 비용·ROI 숫자가 없다 / 주최사의 약점 숫자를 본문에 적은 것은 괜찮나.
**패크크(지원서형)**: 직원 정보 노출 안 되나 / 해당 손님이 아니면 / 직원 업무 부담은 / 왜 하나증권인가 — 식의 "선정 뒤 리스크" 질문.
**소마 기획심의(프로그램형)**: 아이 성장에 따른 모델 정확도 저하 / 유저 유치와 BM / 앱 용량 / UX 복잡도 / 차별성이 흐려질 위험.
**알파프로젝트(학내)**: 외부 모델을 소개·구동만 하는 것 아닌가 / 15주에 가능한가 / 팀원별로 무엇을 하나(복붙 계획은 감점) / 공공성·학교 홍보 기여는.
**CINE:SCOPE 저작권**: 영상 소스 권리는 → 퍼블릭 도메인·CC BY만, 목록 제시.

## 3. 질문을 고르는 법
1. 심사 기준 배점이 큰 항목부터.
2. 산출물에서 가장 약한 항목(판정이 갈리는 숫자, 가정이 많은 기능)을 겨냥.
3. 주최사의 민감 쟁점(국감 지적·제재·최근 사고)을 하나 넣는다.
4. "이미 있지 않나"는 반드시 넣는다.
5. 답은 본문 어디에 있는지 절 번호까지 적는다. 없으면 본문을 고친다.
