# contest-types.md — 공모전 유형별 차이

| 유형 (`--type`) | 예 | 산출물 | 공통 파이프라인에 더하는 것 |
|---|---|---|---|
| **dev** 개발형 | KIC(예선 기획서 → 본선 MVP 19일), 코스콤(MCP 서버+매뉴얼+배포), 현대차 오도(앱+영상+GitHub), 엘리스, 헥토 | 기획서·슬라이드, MVP 계획, MVP, 시연 영상, 저장소·README, 매뉴얼, 발표 | 기능×통과 기준, 평가 하네스, 데모 스냅샷, 매뉴얼, 질의응답 |
| **idea** 아이디어 제안형 | 하나증권(5,000자 본문 + 첨부 3) | 지원서 본문, 보충자료, 화면 예시 | 화면 예시(실제 UI 위에 얹기), 붙여넣기용 txt, 글자 수 |
| **ad** 광고·크리에이티브 | DCA 월드콘·처음처럼·에어리즘 | 브리프보드(인사이트·아이디어·배경·기대효과·방안), 카피, 시안 SVG | 수상작 문법 분석, 장소 판정 기준, 숫자 전환 공식, 어법 검증 |
| **application** 프로그램 지원서 | 패크크 2기, 장학금, SK하이닉스 해커톤 지원서 | 문항별 답변 | 문항→평가 축 매핑, 관통 문장, 심사자 리스크 선제 제거, 표현 교정표 |
| **program** 학내·연수 | 알파프로젝트 신청서, 소마 기획서·중간보고서 | 신청서, 주차별·개인별 계획, 중간·최종 보고서 | 시간·예산 맞추기, 팀원별 계획(복붙 금지), 중간보고서 검증본, 심사 기준 4영역 명시 대응 |

## 개발형에서만 보는 것
- "심사 목적이면 판단이 뒤집힌다": 앱보다 반응형 웹(URL 하나, 심사위원이 직접 만져봄). 화면 수보다 한 흐름의 완성도. 계약이 필요한 외부 연동(마이데이터 등)은 목업 + 직접 입력.
- 발표에서 반드시 '근거 시트'를 시연: "이 판정의 근거는 이 문서 이 문장, 시행일은 이때, 마지막 확인은 오늘".
- 계산·판정은 결정적 코드, LLM은 인터페이스. 신뢰도 낮으면 사람 검토. 단일값 대신 범위·시나리오, 기본값은 보수적.
- 데모는 외부 사정에 흔들리지 않게: 야간 배치 스냅샷(JSON), 오프라인 설치 파일, 시뮬레이션 모드.
- 기존 코드 재사용은 규정 확인(기존/응용/신규 구분 기재).

## 아이디어형에서만 보는 것
- 사건 하나(날짜·기관·숫자)로 시작 → 빈도 → 사람 이야기 → 세 가지로 좁힘.
- 접수 폼 필드(글자 수·첨부 수·파일명)를 먼저 확인하고 그 안에서 쓴다.
- 보충자료는 한 장에 한 증명. 화면 예시는 기존 디자인 체계를 바꾸지 않는다.

## 광고형에서만 보는 것
- 입력: 과제 브리프 + 전년도 수상작 + 카테고리 목록. 먼저 수상작 문법을 뽑는다(이미 있는 접점에 얹기 / 감정(민망함·찝찝함) / 기능의 물리적 은유 / 즉시 구매 연결 / 작품명이 곧 요약 / 숫자 전환 공식 '탄산 22% → 찬바람 22초').
- 브리프 오독 점검(자사 브랜드를 경쟁사로 읽지 않기, 숫자 나열은 힌트).
- 장소·메커니즘 판정 기준표: 결핍의 즉시성 / 장소의 필연성 / 체류 시간 / 혼잡·민원 / 타깃 밀집. 이동 중인 곳 ×, 머무는 곳 ○.
- 카피 어법 검증('처럼'은 때를 가리키는 말에만), 헤리티지 훼손 위험(리뉴얼 해에 로고 해체), 방어 지점 명시(창피 주는 광고로 읽히면 실패, 촬영 프라이버시).
- 사용자가 Claude 안을 연속 기각하고 자기 안을 내는 경우가 많다. 그때는 구조만 손본다(QR을 판매 링크가 아니라 개인화 산출물 수령 장치로, 브랜드 연도를 숫자 자산으로).

## 지원서형에서만 보는 것
- 문항을 평가 축으로 번역하고 1기 심사 기준·주최사 사업 모델을 먼저 조사.
- 관통 프레이밍 한 문장을 모든 문항에 반복("AI로 무엇을 좁히고, 패딧으로 어떻게를 확정").
- 심사자가 선정 뒤 걱정할 리스크를 지원자가 먼저 지운다(거주지·가용 시간·완주 이력).
- 함정 목록·표현 교정표("AI로 디자인을 뽑았다" ✗ → "제가 정한 기준으로 시안 40장을 생성하고 3안으로 압축해 직접 수정" ✓). AI가 틀렸던 경험을 스스로 말하는 것이 신뢰 신호.
- 사용자가 채울 것만 번호로 묻고 【】로 비운다. 증거 첨부 3종 제안.

## 학내·연수형에서만 보는 것
- 양식 항목 추가·삭제 금지면 새 내용은 기존 소항목 안에. 안내문·✅ 상자 삭제, 목차 갱신.
- 선발 기준 영역마다 정면 대응 문장("외부 공개 모델을 '소개'하거나 '구동만' 하는 활동이 아니다"), 감점 항목 선제 차단, 가산점 조건 기재.
- 팀원 이력은 각자 직접. 추정으로 채웠다가 '(기입 필요)'로 되돌린 사례가 있다.
- 중간보고서는 '검증본' 단계를 둔다: 사실 정정, 근거 약한 값 정리, 활동량 지표 삭제, 과장 축소, 검증 원칙 명시(임계 조정 데이터와 평가 데이터 분리, 시뮬레이터 확인은 검증으로 인정하지 않음).
