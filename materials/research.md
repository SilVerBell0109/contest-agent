## 3. 대화에서 드러난 실제 작업 흐름

플레이북 3장의 여섯 단계(요강 → 주제 → 고도화 → 제작 → 검수 → 제출 이후)는 결과물 기준으로는 맞습니다. 대화 기준으로 보면 단계 사이에 **사용자가 던지는 짧은 질문**이 방향을 정했고, 그 질문이 거의 매번 같은 꼴이었습니다. 아래는 하나증권·KIC를 중심으로 다른 건을 겹쳐 본 것입니다.

### 3.1 시작 — 요강 URL을 던지고 전수 추출을 맡김

사용자는 공고 URL이나 포스터를 주고 "조사해 줘"로 시작했습니다. Claude가 한 일은 세 건에서 같았습니다.

- 요강·일정·자격·심사 기준·시상·혜택을 표로 정리 (하나증권: D-26, 본선 10명 서류전형 면제 5년 유효 → 사용자 프로필의 진로 목표 시점까지 유효하다고 바로 연결)
- **운영진 Q&A 전수 읽기** (KIC: 18건. "출처 기재만으로 허용되는 것은 아님", 기존 코드는 기존/신규 구분 기재, 상호평가 최소 투표 수 미달 시 득표 무효(같은 플랫폼 다른 대회는 10표) 등 양식에 없는 규칙이 여기서 나옴)
- **플랫폼 메커니즘 파악** (KIC: DAKER의 ELO 1v1 상호평가 30% + 전문가 70%, 본인 득표 인정 조건, 임시저장≠최종제출)
- **접수 폼 실제 필드 확인** (하나증권: 제목 300자, 본문 5,000자 일반 텍스트, 첨부 3개·10MB·파일명 규칙. 포스터에는 없던 정보)
- 접근 불가한 페이지는 그렇다고 밝힘 (하나증권 안내 페이지 차단 → "직접 열어 확인하셔야 합니다")

### 3.2 분야 선택 — "분야는 어디가 좋을까?"

하나증권 주제 3개 중 선택을 물었을 때 Claude가 쓴 기준은 네 가지였습니다: ① 본인 역량과의 접점 ② 지원자가 몰릴 분야인지 ③ 학생에게 불리한 분야인지(영업점 실무) ④ **취업 목표와 한 줄로 연결되는지**. 추천과 선택이 달랐다는 점이 중요합니다. 사용자는 추천을 참고하되 뒤이은 조사 결과로 직접 정했습니다.

엘리스에서도 같은 축이 나왔습니다. Claude가 일상 문제 3개(안내문 해석·단톡방 공지·마감 관리)를 냈더니 사용자가 **"내가 가려고 하는 직무 관련으로 생각해보면?"** 이라고 되물었고, 직무 연계 3개(모임 정산·고정지출·금융 문서 해석) 중 '모임 정산 에이전트'가 추천됐습니다. 이유는 대사(정산안-송금 대조)·멱등성(중복 영수증)·정합성처럼 **백엔드 역량을 시연하고 면접에서 쓸 수 있다**는 것이었습니다.

### 3.3 주최사 리서치 — "원하는 것 / 아픈 곳 / 남들은 뭘 하나 / 왜 지금 / 빈틈"

하나증권 조사 보고의 구조가 가장 또렷합니다.

1. 주최사가 원하는 것(소비자보호헌장, 신년사, 수상 이력)
2. 주최사의 아픈 곳 — "기획서에서 조심스럽게 활용 가능"
3. 다른 곳은 뭘 하고 있나(주제별 경쟁사 표)
4. 왜 지금인가(법 개정·시행일·사고 통계)
5. 지금 부족한 것(빈틈) ⭐ 표시
6. 시사점: 주제별 추천 아이디어 1개씩 + 강점

KIC는 더 깊게 갔습니다. 조직도 28실, 투자 프로세스 6단계, 투자위원회 구조, 2025~2026 이슈(TPA, 전략투자계정, 인력 이탈, CIO 공석, 국감 지적), AI 도입 타임라인(AI혁신실 신설, 발주 금액), 선행 대회(코스콤 2025·금융 AI Challenge·KIC 논문공모전) 수상작과 심사 방식, **DAKER 팀빌딩 페이지를 크롤링해 경쟁팀 아이디어 11개**까지 모았습니다.

### 3.4 후보 비교와 선택 — "무조건 수상하고 싶은데 둘 중 하나 추천한다면?"

KIC에서 Claude는 A와 B를 양쪽 다 상세히 쓴 뒤 처음엔 "A를 본체로, B를 확장으로"라고 절충했습니다. 사용자가 **"무조건 수상을 하고싶은데 둘중 하나 너가 추천한다면?"** 이라고 다시 묻자 A를 단독 추천했고, 근거를 "아이디어가 더 좋아서가 아니라 수상까지 가는 관문에서 실패 확률이 낮아서"로 들었습니다.

| 관문 | 판단 |
|---|---|
| 예선 상호평가 30% | 일반 참가자가 PDF 두 장을 비교해 직관적으로 고름 → 한 장으로 이해되는 쪽 |
| 예선 전문가 70%(실현 가능성 20점) | 데이터가 전부 실제·공개인 쪽 |
| 본선 구현 완성도 25점(동점 기준 1순위) | 본선 기간 안에 안정적으로 완성할 수 있는 쪽 |
| 본선 신뢰성 15점 | 근거를 그대로 시연할 수 있는 쪽 |
| 발표·Q&A 10점 | 막아야 할 반박이 하나인 쪽 |
| 본인 역량 | 엔지니어링 비중이 커서 사용자 프로필의 강점과 맞는 쪽 |

이어서 "수상 확률을 더 올리는 조건 6가지"를 붙였습니다. 그 뒤 사용자 지시는 "그러면 A로 해서 더 자세히 조사해줘" 한 줄이었습니다.

### 3.5 버려진 후보와 그 이유

### 3.6 중복 점검 — "이거 겹치지 않을 주제일까?"

하나증권에서 사용자가 던진 이 한 문장에 Claude는 두 축으로 답했습니다. **① 이미 출시된 서비스와의 중복**(기능별로 어디에 이미 있는지 표, 해외 사례는 오히려 실현 가능성 근거로 전환) **② 다른 지원자와의 중복 가능성**(아이디어 유형별 높음/중간/낮음 추정). 그다음 사용자가 "안겹칠만한 참신한 주제인지 너가 판단해줘", "저 분야에 대한 자세한 조사. 내가 판단할 수 있도록"으로 이어 갔습니다. 판단을 Claude에게 맡기는 것과 판단 재료를 받아 직접 정하는 것을 번갈아 썼습니다.

### 3.7 리서치 요청의 말투

반복된 문구는 "철저히 조사해줘", "다른 회사에서 실제로 효과를 본 변화나 분야가 있는지, 해외의 선례가 있는지", "최대한 많은 예시와 인과 관계, 주최사에 대한 배경", "내가 판단할 수 있도록"입니다. 수치로 확인된 효과와 해외 선례를 특히 요구했고, Claude는 그에 맞춰 해외 사례를 찾아 넣었습니다.

KIC에서는 리서치 결과를 ✅ 1차 출처 확인 / ⚠️ 2차 출처·추정 / ❓ 미확인 세 등급으로 표기하고, 마지막에 "남은 불확실성" 표를 따로 두었습니다. 1차 출처 확인은 실제로 원자료를 직접 열어 수치를 읽는 식이었습니다.

### 3.8 초안 → 편집 가능한 문서

사용자는 초안이 나오면 **"이걸 구글문서로 만들어줘. 내가 읽고 수정할수있게"** 라고 했습니다. 이후 모든 수정은 같은 Google Doc URL에 덮어쓰는 방식이었고, 소마 Project 메모리에도 "복사해 붙여 넣기 좋은 일반 텍스트, 마크다운 굵게·인용 태그 없이"라는 선호가 기록돼 있습니다. 반대로 KIC는 공식 PPT 템플릿이 있어서 pptx를 파이썬으로 생성하고 매 버전 템플릿 검증 스크립트를 돌렸습니다.

### 3.9 고도화 라운드 — 계기는 항상 사용자의 한 줄

하나증권과 KIC 고도화 라운드의 계기를 늘어놓으면 이렇습니다.

| 순서 | 사용자의 말 | Claude가 한 일 |
|---|---|---|
| 하나 v3 | (잘 쓴 한국어 보고서를 참고해 달라는 취지) | 보도자료·가이드 13개를 읽고 '~다'체 두괄식 보고서체로 재작성 |
| 하나 v4 | **"'이런 일은 드물지 않다.' 이런것처럼 뭔가 사람이라면 안쓸법한 말들을 쓰고있어"** | 지원서 본문 전체를 합쇼체 + 1인칭('제가')으로 전환. B-7 문체 기준이 이때 생김 |
| 하나 최종 | 혹독한 심사위원으로 최종 검토 | 강점 4 / 약점 6 + 접수 순서 안내 |
| KIC 최종 | "아직 AI 같다" + 문장 한 쌍을 예로 지목 | GitHub 한국어 AI-티 가이드 5개를 읽고 헤드라인을 숫자·명사구로, 'N가지입니다' 제거, 1인칭 경험담 추가 |

패턴이 보입니다. **내용 보강 → 문체 → 사실성(경험) → 심사위원 모의(1~2회) → 문체 재점검** 순서이고, 심사위원 모의는 Claude가 자기 산출물을 비판한 뒤 사용자가 한 단어로 승인하는 방식이었습니다. plan.md에 "v4 변경 기록(사용자 승인 '전부 반영')", "v5 변경 기록(사용자 승인 '반영해줘')"처럼 승인 문구까지 기록해 두었습니다.

### 3.10 문체 교정 루프의 실체

세 산출물(하나증권 본문, KIC 슬라이드, Table_shot 발표)에서 같은 루프가 돌았습니다.

1. 사용자: "AI 같다" + 구체적인 문장 하나를 예로 지목
2. Claude: 외부 기준을 찾음 — 한국어 보고서 작법 13개 / GitHub AI-티 가이드 5개(humanizer-ko, anti-korean-ai-slop, k-maltu, K-Humanizer, korean-report-skills) / 실제 FEConf 2022 발표 덱
3. 재작성 후 **검증 스크립트**로 금칙 표현 0건 확인(줄표, '~에 대한', '~을 통해', '~적인', '드물지 않다', 마크다운 `**`, '제가' 빈도)
4. 결과를 자산화 — 사용자가 "보고서 말투를 파일로 저장해 다음에도 쓰게" 요청 → `~/Downloads/보고서_말투_가이드.md` + korean-report-tone 스킬, 메모리 preferences에 등록(2026-11-05)

이미지에도 같은 지적이 왔습니다. 화면 목업이 "AI 같다" → 알약 배지 제거, "~해 드려요" 상담 말투 제거, 라벨을 실제 앱 문구처럼 단순화. 슬라이드에는 "프로젝트 외의 내용은 다 빼줘. 너무 사족이 많아" → 장당 제목 한 문장 + 근거 하나만 남김.

### 3.11 시각자료 제작 방식

- 하나증권 화면 예시: 실제 앱 UI를 Google Play 스크린샷·App Store·공식 가이드 영상에서 조사 → HTML/CSS + Playwright로 렌더(실제 색·하단 탭·카드 스타일 맞춤) → 적용 전/후 합성 → A4 가로 PDF(10MB 이내, Pretendard) → 화면마다 기획서 항목 번호 표기

### 3.12 제출 공정

하나증권에서 끝까지 확인한 것: 접수 폼 실제 필드 → 붙여넣기용 txt(□·①·→처럼 일반 텍스트에서 살아남는 기호만) → 글자 수 검증(줄바꿈을 2자로 세는 경우까지) → 문서와 txt 완전 일치 확인 → **모든 통계·날짜·인용을 원출처와 재대조** → 접수 순서 안내(타이머 1시간 40분이 있으니 들어가자마자 임시저장) → AI 활용 문장을 "실제 작업 범위보다 축소된 표현"이라며 사실대로 고침("자기 신고는 심사위원이 가장 먼저 의심하는 항목이니 축소 표현은 오히려 손해").

## 4. 유형별로 다른 작업 방식

플레이북 7.1은 모드를 세 가지(아이디어 공모전 / 개발 공모전 / 학내·연수 프로그램)로 잡았습니다. 채팅을 보면 두 유형이 더 필요합니다.

### 4.1 광고·크리에이티브(DCA 3건) — 플레이북에 없음

작업 방식이 완전히 다릅니다.

- **입력**: 과제 브리프 사진 + 전년도 수상작 사진 + 카테고리 목록. 사용자 요청은 "42회 수상작을 참고해 수상권 상위 1%의 아이디어"
- **수상작 문법 분석**이 먼저입니다. 42회 두 편에서 뽑은 문법: 새로 만들지 않고 이미 있는 접점에 얹기 / 시원함이 아니라 민망함·찝찝함 같은 감정 / 기능의 물리적 은유 / 즉시 구매 연결 / 작품명이 곧 아이디어 요약 / **숫자 전환 공식**(그랑프리 '탄산 22% → 찬바람 22초'를 에어리즘 '코튼이 한 번 마를 때 에어리즘은 두 번', 월드콘 '1986년 → 19.86초'로 변주)
- **브리프 오독 방지**: 처음처럼 브리프의 '새로'를 경쟁사로 읽으면 자사 브랜드를 공격하게 됨을 짚음. 도수 나열(19.8→16)은 "헤리티지를 숫자로 갖고 있으니 그 문법을 쓰라는 신호"로 해석
- **장소 판정 기준표**(사용자 기준을 Claude가 표로 만든 것): 결핍의 즉시성 / 장소의 필연성 / 체류 시간 / 혼잡·민원 / 타깃 밀집. 월드콘에서 사용자가 쓴 기준이 에어리즘 에스컬레이터 안에 그대로 재사용됨
- **사용자가 주도**: Claude 안을 연속 기각한 뒤 자기 안(DOOH 4개 전광판 × 프리미엄 3종)을 냈고, Claude는 구조만 손봄(QR을 판매 링크가 아니라 개인화 영상 수령 장치로, 19.86초 자산화)
- **어법·카피 검증**: '첫 승진처럼'이 안 붙는 이유를 문법으로 설명하고 배치로 해결('첫 승진 / 처음처럼')
- **방어 지점 명시**: "창피 주는 광고로 읽히면 실패", 촬영 스크린의 프라이버시 설계를 브리프보드에 한 줄 넣으면 실행 가능성 가점
- 산출물: 브리프보드 문안(인사이트·아이디어·백그라운드·기대효과·방안), Figma용 SVG 화면

### 4.2 프로그램 지원서(패크크·소마) — 플레이북에 부분만 있음

- **문항 → 평가 축 매핑**: 패크크 3문항을 완주 가능성 / 제작 가능성·패딧 활용 / 펀딩 성공 가능성으로 번역하고, 1기 심사 기준과 주최사(패딧) 사업 모델을 먼저 조사
- **관통 프레이밍 한 문장**을 세 문항에 반복: "AI로 무엇을 만들지를 좁히고, 패딧으로 어떻게 만들지를 확정한다"
- **심사자가 선정 뒤 걱정할 리스크를 지원자가 먼저 지움**: "필요하면 당일 방문 가능" 한 문장이 어떤 수식어보다 강하다고 판단
- **함정 목록과 표현 교정표**: "AI로 디자인을 뽑았다"(✗) → "제가 정한 기준으로 시안 40장을 생성하고 3안으로 압축해 직접 수정"(✓). AI가 틀렸던 경험을 스스로 말하는 것이 신뢰 신호
- **사용자가 채워야 할 것만 묻기**: 확인 질문 4개 → 사용자가 "1. 있음 2. 나중에 3. 모르겠음 4. 2인팀·주2회·거주 구"처럼 번호로 답 → 【 】 자리표시로 초안 → 사용자가 자기 문장으로 쓴 지원동기를 붙여 넣음
- **증거 첨부 3종** 제안(시안 압축 과정, 렌더↔도식화 대응표, 실물 사진 — "3번이 있으면 1등 확률이 크게 올라감")
- 자기소개서: 전면 재작성이 아니라 평가 기준에 맞춰 문장만 다듬고 사실관계는 그대로. 공모전 경험을 "동기 → 주제·구현 → 역할 → 배운 점 → 결과"로 서술

### 4.3 개발형(KIC·코스콤·엘리스·K-Invest)

플레이북이 가장 잘 다룬 유형입니다. 채팅에서 추가로 확인된 것:

- **"공모전·데모 심사가 목적인 경우야"** 한 마디에 판단이 뒤집힘(K-Invest): 앱 → 반응형 웹. 이유는 "심사위원이 직접 만져보게 하는 것이 가장 강력", "설치를 요구하는 순간 아무도 안 함". 화면 수보다 **한 흐름의 완성도**, 마이데이터 실연동은 금지(목업 + 직접 입력), 발표에서는 **근거 시트를 반드시 시연**("AI가 그럴듯하게 답하는 서비스는 흔하고, 판정 근거·시행일·최종 확인일까지 보여 주는 서비스는 드물다")
- 코스콤 테스트 대화 3건은 **사용자가 자기 제품의 테스트 사용자**가 된 기록입니다. 45세 중위값 케이스를 넣고 "저축액을 증액하고 은퇴 후 월 지출을 줄이는 방향으로 수정해줘. 은퇴 시기는 더 늦추지 않을거야", "가장 절세하는 인출 방법은?", "위 답변을 전부 포함한 종합 PDF"를 요청했습니다. 플레이북의 '조정 순서(지출 감소 → 저축 증액 → 은퇴 연기는 최후)'가 이 대화에서 나왔고, 제출물 목록의 'Claude 대화 공유 링크'가 바로 이 대화들일 가능성이 높습니다(추정)
- 소마 BM 설계 채팅: "소마 심사자는 이 숫자를 어떻게 뽑았나를 검증하므로" R2 실단가에서 역산한 손익분기 용량 표를 만들고, 침투 적자를 "지원 신청 논리"로 전환

### 4.4 아이디어 제안형(하나증권)

플레이북 2.4와 6.1이 이미 정확합니다. 채팅에서 덧붙일 것은 3.2~3.9의 과정뿐입니다.

## 5. 사용자(최종은)가 반복해서 적용한 기준

스킬이 사용자 대신 판단할 때 써야 할 기준입니다. 전부 사용자가 대화에서 직접 말했거나 선택으로 보여 준 것입니다.

| 기준 | 근거가 된 대화 |
|---|---|
| **수상이 최우선**, 아이디어의 참신함보다 실패 확률 | "무조건 수상을 하고싶은데" (KIC), "수상권 상위 1%" (DCA), "1등을 해서 바우처" (패크크) |

| 겹치지 않는 주제 — 기존 서비스와도, 다른 지원자와도 | "이거 겹치지 않을 주제일까?", "안겹칠만한 참신한 주제인지" |
