# 보충자료 구성 (첨부 제한이 있을 때, 예: 3개)

> 각 장은 한 가지만 증명한다. 화면 예시는 기존 앱 화면 위에 제안 기능만 얹고, 화면마다 기획서 항목 번호를 단다. 가상 수치·시각에는 '가상'을 명시한다.

## 첨부 1 — 사건 타임라인
| 일자 | 주체 | 무슨 일 | 사용자에게 생긴 일 | 출처 |
|---|---|---|---|---|
(보도로 확인된 사례만. 주최사 사례가 있으면 포함)

## 첨부 2 — 원인과 피해의 연쇄
원인 목록 → 사용자에게 일어나는 순서 → 수치 → 현재 보상·구제 체계

## 첨부 3 — 사용자 경험 전후 비교 (같은 시각표, 분 단위)
| 시각 | 적용 전 | 적용 후 |
|---|---|---|

## 별도 — 화면 예시 문서
1. 머리말: 기준 앱·버전, 참고한 자료(공식 가이드·스토어 스크린샷), 수치·시각은 가상 시나리오임, 실제 화면과 다를 수 있음
2. 시각표(평시 → 감지 → 중 → 후)
3. 적용 전·후 화면 비교
4. 흐름도(단계마다 "(기획서 2-1 ①)" 식 번호)
5. 화면별 설명 표: 화면 | 설명 | 대응 기획서 항목
6. 화면 기준과 참고: 기존 디자인 체계(색·카드·탭)를 바꾸지 않는다, 문구는 컴플라이언스 검토 전제

## 제작 규칙
- 실제 UI 조사(스토어 스크린샷·공식 영상) → HTML/CSS로 렌더(2x) → 장식 배지·상담 말투 제거(AI 티) → PDF(용량 제한 확인, 한글 폰트 임베드)
- 파일명 규칙(예: 지원자명_보충자료명.pdf)과 용량 제한을 brief.md에서 확인
