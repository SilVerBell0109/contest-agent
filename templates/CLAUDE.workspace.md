# {{NAME}} — 작업 공간 규칙

이 폴더는 공모전 **{{NAME}}** 전용이다. 다른 공모전 자료가 들어오면 작업하지 말고 먼저 확인을 구한다(채팅 교차 오염으로 폐기된 초안이 실제로 있었다).

## 작업 순서
리서치 → 계획 → 사용자 승인 → 구현. 코드는 plan.md 승인 뒤에만 쓴다. 성공 기준을 먼저 정의하고 실행한다. 요청한 것만 만든다.

## 진실의 원천
1. `30-refine/evidence.md` — 모든 사실은 여기의 E-ID를 단다.
2. `40-spec/PRD.md`, `40-spec/SRS.md` — 승인 뒤에는 산출물의 기능·수치·용어는 여기서만 가져온다. 바꾸려면 스펙 변경 기록을 먼저 쓴다.
3. `CONTEST.md` — 단계·관문·결정. 단계가 바뀌면 즉시 갱신한다.

## 표기 규칙
- 확인 못 한 값 `[확인 필요]`, 가정 `[가정]`, 가상 예시 `[예시값]`, 사용자가 채울 것 `【 】`. 제출본에는 0건.
- 추측은 "제 추측입니다", 직접 집계는 조건(기간·질의·집계일)과 함께.
- 사람(팀원·본인)의 경험·이력·연락처는 생성하지 않는다. 비우고 묻는다.

## 문체
- 지원서·기획서 본문: 합쇼체('~입니다') + 1인칭('제가'), 평소 쓰는 말. 줄표·굵게·이모지 금지.
- 양식이 개조식이면 개조식 유지. 주최사 호칭(예: '손님')을 따른다.
- 제출 전 `/contest:verify`. 금칙 표현은 `scripts/check_style.py` 기준.

## 보안
- API 키·시크릿은 `.env`에만. 코드에 하드코딩 금지. `.env`는 커밋하지 않는다.
- 데이터·모델·영상은 라이선스를 확인하고 evidence.md에 조건을 적는다.
