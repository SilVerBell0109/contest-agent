# 제출 전 체크리스트 — {{NAME}}

> 괄호 안은 실제로 새어 나갔던 실수의 출처. 전부 ✅가 되어야 제출한다. `/contest:verify`가 스크립트 항목을 자동으로 채운다.

## 1. 사실과 수치
- [ ] 숫자마다 E-ID(출처)가 있다. 직접 집계는 조건 각주가 있다 (KIC [4])
- [ ] 시연·시나리오 숫자가 실측과 맞다 ('하루 42건' → 평균 24건)
- [ ] 같은 숫자가 여러 곳에서 같다. 요약과 본문이 같다 (소마 요약 BM 불일치)
- [ ] 가상 수치·화면에 '가상'·'예시값' 표기
- [ ] 따옴표 인용이 원자료에 있다 (소마 설문 인용)
- [ ] 절대 표현('전혀', '모두', '사실상 0', '기존에 없다') 점검
- [ ] 활동량(이슈·PR 수)보다 결과 지표. 측정 안 한 것은 '측정하지 않음'. 구현 완료/계획 구분
- [ ] 평가 표본이 타깃과 다르면 밝혔다 (8~18세 vs 0~7세)

## 2. 남은 흔적 (scan_placeholders.py)
- [ ] 【】, [확인 필요], [가정], [예시값], [작성 예정], (기입 필요), TODO 0건
- [ ] 대화 중 지시·메타 문구 0건 ("(사용자 원칙: …)", "…png를 삽입", "배점에 유리")
- [ ] 양식 안내문·✅ 질문 상자 삭제
- [ ] 마크다운 잔재(**, #, 물결표 취소선) 0건
- [ ] 다른 문서에서 복사돼 맥락에 안 맞는 문구 0건 (코스콤 인출 원칙 복붙)

## 3. 구조와 번호
- [ ] 목차 갱신, 빠진 제목 없음
- [ ] 절 번호·상호참조 일치 (7.4 → 7.6 건너뜀, 없는 9절 참조)
- [ ] 그림 캡션과 이미지 위치 일치
- [ ] 본문에서 인용하지 않은 참고문헌 없음

## 4. 일관성 (traceability.md §4)
- [ ] 새 기능이 목표·KPI·유저플로우·일정·역할·예산·기대효과에 모두 반영 (CINE RAG)
- [ ] 팀원 변경 시 인원수·동아리·역할표·개인 계획·동의서·예산 한도 동시 수정
- [ ] 텍스트판·그림판 등 산출물끼리 내용 일치
- [ ] 서비스명·팀명·주최사 호칭·기능 이름 통일

## 5. 분량과 형식 (count_chars.py)
- [ ] 글자 수(공백 포함, 줄바꿈 2자 기준으로도) · 페이지 · 글자 크기 · 파일 형식·용량 · 첨부 개수 · 파일명·메일 제목 규칙 · 참조(CC)

## 6. 개인정보와 보안
- [ ] 심사 자료에 이름·연락처·소속 기재 금지 규정 준수
- [ ] 공유 링크·GitHub에 실명·계정·API Key·민감정보 노출 없음, .env 미포함

## 7. 라이선스
- [ ] 데이터·모델·영상·오픈소스 이용 조건과 비상업 조건 표, 뺀 데이터와 이유

## 8. 심사표 대응
- [ ] 평가 항목·✅ 질문마다 본문 어디가 답하는지(traceability §1), 감점 선제 대응, 가산점 조건 기재

## 9. AI 활용 고지
- [ ] 실제 작업 범위와 맞는 문장(축소 표현 금지)

## 10. 문체 (check_style.py, humanize-scan)
- [ ] S1 0건, 변경률 30% 이하, 양식이 개조식이면 개조식 유지, 주최사 호칭 준수

## 11. 접수 절차
- [ ] 폼 필드 제한 확인 → 붙여넣기용 txt(일반 텍스트에서 살아남는 기호만) → 들어가자마자 임시저장 → 첨부 파일명 규칙 → 최종 제출 버튼(임시저장 ≠ 제출)
