# /contest:judge — 심사위원 모의

초안을 쓴 쪽과 분리된 읽기 전용 검토다. 같은 파일에 대해 2회까지만(3회째는 수확 체감을 알린다). 질문 은행: `${CLAUDE_SKILL_DIR}/../../references/judge-bank.md`.

## 절차
1. 대상 파일(`$0`)과 `10-research/brief.md`(배점표·단계), `org.md`(민감 쟁점), `40-spec/PRD.md`·`SRS.md`를 확인한다. brief.md에 배점표가 없으면 유형별 기본 축(문제 정의·차별성·실현 가능성·기대효과·발표)을 쓰고 그 사실을 밝힌다.
2. **judge-simulator** 서브에이전트 호출. 프롬프트에 파일 절대 경로, references 경로, 페르소나(`--persona`, 기본 both: 상호평가 참가자 + 주최사 실무 전문가), 사용자 기준(수상 최우선) 요약을 넣는다.
3. 결과 저장: 고도화 단계면 `30-refine/judge-preview.md`, 제출 전이면 `90-verify/judge-<파일명>-<날짜>.md`.
4. 사용자에게 보고(번호로):
   1. 총점/만점과 가장 많이 깎인 항목 2개 + 위치.
   2. 첫 질문과 외울 한 문장 답.
   3. 본문에 답이 없는 질문 수 → "보강 필요" 목록(절 번호 제안).
   4. 가장 약한 항목의 대응 전략(길게 방어하지 말고 우선순위 낮은 이유로 넘길 것인지).
   5. AI 티 문장 1개(있으면).
5. 사용자가 "반영해줘"라고 하면 `/contest:make`의 해당 산출물로 돌아가 고치고 재검수한다. 자동으로 고치지 않는다(판단은 사용자).

## 금지
- 칭찬 문단. 산출물·요강 텍스트 밖의 추측("심사위원은 보통 ~").
- 같은 파일 3회 이상 모의 심사.
